# 140 工具调用事实锚定与旧结果防幻觉

## 目标

降低角色把上一轮工具结果、上一轮台词或未实际执行的动作说成当前事实的概率。

## 诊断

- `core/pipeline.py::run_agentic_loop()` 的 `11.5_tool_nudge` 只是本轮软提示。
- 主动调度路径目前不在本工单范围内；本工单只处理 owner chat/tool loop。
- `10_tool_result` 和 `10.5_action_trace` 都可能让历史动作看起来像当前动作。
- 普通非-function-calling 路径不能依靠模型自行决定真实工具调用。

## 实施范围

1. 对明确的查询/操作意图增加确定性 pretool 路由或显式“本轮必须调用”标记。
2. 给 tool result 增加本轮边界、生成时间和有效性语义；旧结果必须明确标注为历史参考。
3. 增加输出校验：本轮没有成功 tool call 时，禁止生成“已经查到/已经控制/已经完成”等完成式断言。
4. 保留现有 `execute(origin=...)` 闸门和 action trace，不绕过统一工具入口。
5. 补充成功调用、工具失败、旧结果误用、工具未暴露四类回归测试。

## 验收

- 明确要求调用工具的消息不会只返回口头承诺。
- 本轮没有成功调用时，回复不会声称动作已完成。
- 历史 tool result 仍可被检索，但不会以“当前结果”注入。
- `pytest -n auto` 指定相关 tool-loop/pretool 测试通过。

## 备注

这不是单纯换模型的工单；模型升级只能降低概率，不能替代事实校验。
