# 临时工单 1：实现前审计

- 管理面“观测”导航在 `admin/static/index.html`；页容器由 `data-page-fragment` 注册，`admin/static/js/core.js::goto()` 负责 fragment 加载和页面 loader。观测页逻辑集中在 `admin/static/js/observability.js`。
- 仅有的常驻调度循环是 `core/scheduler/loop.py::_loop()`；它已在每个 tick 内调用 `WakeBridge().drain_due()`，因此 autonomy 只能作为该 tick 的一次扫描，而不是新 worker。
- 共享主动发言账本为 `core/scheduler/proactive_ledger.py`。`record_send()` 是既有发言出口的记账点；owner 的真实用户输入在 `main.py::handle_message()` 和 `admin/routers/chat.py::run_owner_chat_turn()` 进入 `mark_user_active()`。
- 普通对话互斥锁是 `core/conversation_gate.py::conversation_lock()`；状态机在 `core/scheduler/state_machine.py`，可提供 `CHATTING / QUIET / RESTLESS`。普通工具循环在 `core/pipeline.py::run_agentic_loop()`，不能复用为 autonomy 语义。
- MCP 工具的本地 policy/effect 在 `core/mcp_client.py` 注册到 `_TOOL_REGISTRY`；远端 `readOnlyHint` 不是授权依据。dispatcher origin 白名单在 `core/tool_dispatcher.py::_EXECUTE_ALLOWED_ORIGINS`。
- 耐久状态应通过 `core/sandbox.get_paths()` 与 `core/safe_write.safe_write_json()` 写入；本实现新增 autonomy 专用 DataPaths，不把状态塞入现有 scheduler cooldown 或 Wake Bridge 文件。
- Wake Bridge 的 `_drain_scope()` 会把“没有成功 assistant turn”按 gated/backoff 重试；需把明确的长期 speech suppression 变成 terminal disposition，其他临时阻塞继续保留 lease/backoff。

结论：autonomy 将采用独立 job/run/audit store、独立 agent loop 与 talk gate；只复用 scheduler tick、conversation lock、Dream Guard、dispatcher 和 ProactiveLedger 的底层边界，不调用 `_pipeline_send()`。
