# Brief 227 · 视觉观察人工审计与习惯固化准入（替代 Brief 62）

> 状态：`planned`，默认仍是 shadow-only，不向 profile/identity/episodic 写入习惯。
>
> 本单替代已退役的 Brief 62。将 shadow 观察从“能收数据”推进到“可以被人工复核”，
> 通过后再另立实现工单接入 habit 固化。观察窗口改为连续 7 天；这不是自动放宽安全条件，
> 只是先建立一套可验证的小范围准入。

## 1. 当前事实

- 后端入口是 `POST /perception/visual`；原始图片只在内存中处理，服务端不把原图写盘。
- 后端 trace 在 `data/runtime/perception/visual_trace.jsonl`，管理面可通过
  `GET /perception/visual-trace`（`state.read`）查看；这里只含时间、scene、activity、
  confidence、短 caption 或 dropped 原因，保留 30 天。
- `scripts/audit_visual_trace.py` 只打印按日分布和 dropped 统计，不提供原图，也不能单独证明 caption 正确。
- 因此，历史 trace 找不到对应原始画面时，该条必须标记 `un审计/invalid sample`，不能凭 caption 猜测通过。

## 2. 画面到哪里找

按以下优先级寻找与 trace 时间对应的本地画面：

1. **桌宠客户端本地截图缓存/调试目录**：在 Emerald-client 的视觉观察实现和本地 app data 中查找按时间或 frame hash 保存的原始截图。先确认文件确实来自视觉观察采样，不要把普通上传、coplay 或手机 screen-context 图片混进来。
2. **运行中的桌宠现场复现**：如果历史截图没有保留，打开桌宠“设置 → 视觉观察”，确认本地开关和后端 `visual_perception.enabled` 都开启，重新采样并同时保存“本地截图 + trace 返回时间”。这批只能作为新样本，不能冒充历史样本。
3. **后端目录仅用于对照 trace**：`data/runtime/perception/visual_trace.jsonl` 没有原图；
   `data/cache/image_cache/` 是媒体上传描述缓存，不是视觉观察原图，不能作为本审计画面来源。
4. **找不到画面时停止该条审核**：不要从 caption、日志或 API 调用记录反推画面内容；标记 `un审计`，并在最终统计中从“有效抽查数”排除，同时记录缺失数量。

## 3. 7 天准入与抽样

1. 先确认 trace 在连续 7 个自然日都有有效运行记录；中断一天即重新起算。
2. 从这 7 天内 `dropped` 为空且包含 `scene/activity/confidence/caption` 的记录中，随机抽取至少 50 条；记录 trace 时间和本地截图路径/文件 hash。
3. 若有效可对照样本不足 50 条，准入失败，不得用 dropped/cooldown 条目补足。
4. 审计表放在本地未跟踪目录或受控备份中，不提交截图、caption 原文、用户身份或绝对路径。

## 4. 每条画面的人工判定

审计者逐条查看本地原图，并填写：

```text
trace_time | local_frame_hash | sensitive_actual | sensitive_missed
scene_ok | activity_ok | caption_supported | forbidden_detail
decision(pass / hallucination / sensitive_missed / un审计) | note
```

- `sensitive_missed`：画面含支付、密码、证件、账号、私密聊天等敏感信息，但 trace 没有 `dropped=sensitive`。
- `hallucination`：scene/activity/caption 包含画面无法支持的事实、身份、情绪、具体人名/作品名或屏幕文字猜测。
- `forbidden_detail` 即使 scene/activity 大致正确，也应判不通过；不要用“总体看起来没问题”覆盖具体违规。

## 5. 通过标准

必须同时满足：

- 连续 7 天有有效 shadow 记录；
- 至少 50 条可回看原图的有效样本；
- `hallucination / 有效样本 < 10%`；
- `sensitive_missed = 0`；
- scene/activity 分布由用户确认与实际作息大体一致；
- 审计摘要包含样本数、各类失败计数、trace 版本/代码版本和复核日期，但不包含原图或敏感正文。

## 6. 通过后的实现边界

准入通过后，另立实现工单开发 `core/scheduler/triggers/habit_consolidate.py`：规则聚合近 14 天
高置信度 trace，每日最多新增/更新 1 条，经 Brief 45 的 profile 冲突裁决入口写入 `habit`。
在那之前不得新增 writer，不得把视觉 caption 注入 prompt、identity 或 episodic。

## 7. 必须补的观测与回归

- 管理面提供审计摘要的只读状态（有效天数、样本数、失败计数、最近审核时间），不返回原图。
- 回归测试覆盖：7 天窗口、中断重算、随机抽样不足 50、敏感漏判、caption 禁止细节、
  无原图时 `un审计`、测试数据隔离和 shadow-only 不写记忆。
- 桌面端若新增截图保留或导出能力，必须同步三仓接口文档，并明确本地 retention、删除和权限。
