## 1. 定位

现在有两块视觉模型配置，UI 覆盖程度不一样：

1. **`vision:`** 段（`config.yaml`）——`visual_perception`（Brief 56 shadow 观察）用的通用视觉模型。
   已经有管理面板 UI：`GET/PUT /vision-params`（`admin/routers/settings_llm.py:310-346`），对应
   `index.html` 里的"Vision Model"卡片（表单大约在 751-780 行，JS 在 3705/3733 行附近）。这块不用动，
   只是作为下面这块的参照样板。
2. **`phone_control_vision:`** 段——手机自动化（"computer use 手机版"）单独覆盖的视觉模型，只覆盖会变
   的字段（通常只填 `model`），`api_key`/`base_url`/`enabled` 留空时继承 `vision:` 段
   （`core/phone_control/vision_client.py::get_phone_control_vision_config()`）。**目前完全没有
   管理面板入口**，只能手动改 `config.yaml`。`admin/routers/phone_control.py` 里的
   `GET /phone_control/status` 只读了这个 config 判断 `vision_configured` 布尔值给手机端用，不提供
   任何写入路径。

用户原话：不想再手动改 config.yaml，想让"手机的视觉"和"普通截图的视觉"这两条模型路由都在管理面板
"模型路由"那块统一管理，跟现在 LLM 那套 `model_presets`/`routing_profiles`（预设 + 路由方案两层）如果
能顺手对齐最好，对不齐也没关系，别为了对齐搭太多脚手架。

## 2. 现成参照：LLM 那套 model routing UI 有多大

`settings_llm.py` 里已经有一整套预设 CRUD + 路由方案 CRUD：
`GET /model-presets`、`POST /model-presets/bootstrap`、`PUT /model-presets/active-routing`、
`GET /model-presets/routing-profiles`、`PUT /model-presets/presets/{name}`、
`DELETE /model-presets/presets/{name}`、`PUT /model-presets/routing-profiles/{name}`、
`POST /model-presets/presets/{name}/test`。对应 `index.html` 里"模型路由"分区，HTML 约 168 行
（1382-1550 附近）+ JS 约 250 行（4062-4310 附近），合计 400+ 行。这是"多预设 + 路由方案"这套模式
完整实现的工作量参考——视觉路由不需要做到这么复杂，两个视觉配置（通用 + 手机覆盖）没有"多个 profile
互相切换"的需求，抄样式/审美就够，不用抄整套 CRUD 骨架。

## 3. 要做的事（最简版本，够用就行）

- 后端：加一个端点管 `phone_control_vision:` 段的读写（可以另起 `GET/PUT /vision-params/phone-control`，
  也可以直接扩展现有 `/vision-params` 让它顺带带出/写入这个子块——两种都行，别纠结，选一个改动小的）。
  写入时空字段就是"跟随通用视觉模型"，别强制用户填满。
- 前端：在"Vision Model"卡片旁边或下面加一小块"手机自动化视觉覆盖"，UI 上表达清楚"留空 = 继承左边
  这套通用配置"，不是两套完全独立的表单。
- 不用做的：不用做成 `model_presets` 那种多预设下拉切换，两个视觉配置固定就是"通用" + "手机覆盖"这
  两个坑位，写死就行，不用为了"以后可能要第三个视觉场景"预留扩展性。

## 4. 验收

- config.yaml 里两段视觉配置都能在面板改，不用手动编辑文件。
- `phone_control/status` 的 `vision_configured` 判断逻辑不用改（还是读 merge 后的结果）。
- 面板改完之后 `phone_control_vision.model` 手动测一下确实生效（比如临时改成一个明显不同的模型名，
  跑一次 phone_control 调试端点，确认 `vision_client.py` 真的用了面板填的值，不是缓存了旧的）。
