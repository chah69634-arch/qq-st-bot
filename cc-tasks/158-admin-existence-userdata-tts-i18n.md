# Brief 158: Admin「存在」重组、用户数据资产管理、TTS 角色化选择与 i18n 可逆修复

## 背景

当前后台管理面板存在四类问题：

1. 「记忆与成长」及「只读观测」按内部模块拆成大量页面，多个页面只是输出裸 JSON，普通用户无法据此判断系统是否正常。
2. 「资源完整性」「运行信号」「触发器目录」「API 契约检查」彼此相关但入口分散；它们并不都等同于通道在线状态，也不能压缩成一个含义不清的绿灯。
3. 英文切换回中文后，当前 DOM 能刷新，但部分未访问或懒加载页面仍会半英半中。旧式翻译依赖 `WeakMap` 保存首次见到的文本；节点若在英文状态下首次插入，英文可能被错误保存成“原文”，中文恢复不再可靠。
4. `userdata/` 缺少面向用户的安全资产管理入口；TTS 的参考音频和模型字段仍要求手填路径，角色级 `presence_ext.tts_preset` 也没有在 TTS 面板中形成可理解的配置流程。

## 总目标

- 将「记忆与成长」改名为「存在」，把与角色持续存在相关的状态、成长、感知和互动结果组织到一个可理解的入口中。
- 不再保留裸 JSON 观测页；保留必要的后端只读能力，但前端必须转成摘要卡、状态、表格、时间线和可执行说明。
- 新增「对话与角色 → 用户数据」，安全管理除角色卡、破限和世界书之外的私有 authored 资产。
- TTS 改为“发现已有资源后选择”，并支持按角色查看、绑定和试听有效配置。
- 修复中英切换的全局可逆性，覆盖已经加载和之后才懒加载的页面。

## 事实边界

- `userdata/` 是私有 authored 资产根，不是 `data/` 运行态；所有新增路径必须通过 `DataPaths` / `AssetRegistry`，并登记 `core/data_registry.py`。
- 新写入只进入 `userdata/`。`bundled/` 和旧 `assets/`、`characters/`、`content/characters/` 只允许作为兼容读取来源；不得迁移、覆盖或删除真实旧资产。
- 当前后端可实际读取：通用表情包、角色专属表情包、角色 authored 内容、GSV 参考音频/模型路径。
- 当前 `live2d_model` / `model_3d` 只是角色卡字符串绑定；桌面端从自身本地资源目录加载模型。没有建立后端托管与桌面消费契约前，不得把“上传成功”显示成“桌面端可用”。
- API 契约检查只验证后端可产出的 desktop action type 是否被客户端源码识别；它不证明 WebSocket、HTTP、鉴权或真实发送链路在线。
- 聊天日志、Prompt、触发器样本和隐性状态包含高敏感内容，不能因为页面合并而降级权限或在总览中展示正文。

## A. 导航与「存在」信息架构

### A1. 导航调整

- 将导航组「记忆与成长」改名为「存在」（英文 `Existence`）。
- 「存在」下放置：
  - 存在总览
  - 记忆
  - 成长
  - 支出
  - 视觉
  - 群聊仲裁
- 「支出」「视觉」「群聊仲裁」从原只读观测组迁入「存在」，保留原 deep link 或提供兼容重定向，不得让已保存页面失效。
- 「情绪·花园」「梦境状态」「隐性状态」不再各占一个裸 JSON 导航页：
  - 情绪、花园、梦境当前态进入「存在总览」的可读状态卡；
  - 梦境详细状态同时可从「梦境设置」进入；
  - 隐性状态放入「存在 → 记忆」的高级折叠区，默认隐藏具体值并解释数据含义。
- 删除当前只有短期记忆 JSON 的「记忆探查」前端页；统一到新的「存在 → 记忆」。后端读取接口先保留，完成调用方审计后再决定是否删除。
- 聊天日志不放入「存在」总览。迁到「故障排查 → 内容审计」，默认折叠，并明确显示敏感内容警告。

### A2. 存在总览

不得渲染原始 JSON。至少提供：

- 当前角色与用户作用域。
- 当前情绪：名称、强度/更新时间、无数据状态。
- 花园：植物数量、待处理事件、最近浇水/收获时间、异常提示。
- 梦境：现实/梦境/挽留/冷却等用户可理解状态、当前梦是否活跃、最近一次结束时间、统计摘要。
- 记忆：各层条目数量、最近写入、召回是否可用、来源隔离提示。
- 成长：近期练习、兴趣和作品摘要。
- 视觉、支出、群聊仲裁：各显示一张摘要卡并链接到详情页；不能在总览泄露截图正文、账单秘密或群聊原文。

每张卡必须区分：正常、未启用、尚无数据、需要关注、读取失败。不得把“未启用”显示成故障，也不得把“接口成功返回”显示成业务链路成功。

### A3. 记忆详情

将现有记忆摘要、召回轨迹、向量库、印象溯源和隐性状态组织成同一页的标签或分区：

- 概览：各层数量、更新时间和简短用途。
- 记忆内容：分页、来源、时间、强度/状态；不默认展开全部正文。
- 召回轨迹：本轮查询命中了哪些层、时间过滤、隔离来源；使用人类可读标签。
- 溯源：谁/哪条链路写入、何时写入、变更摘要。
- 隐性状态：解释字段含义、更新时间和来源计数；Dream Snapshot 单独标记为只读快照。

原始 payload 如仍对开发排障必要，只能放在 `admin` 权限控制的“复制诊断数据”动作中，默认不渲染，且必须沿用现有脱敏规则。

## B. 系统诊断合并页

新增一个「故障排查 → 系统诊断」页面，移除以下四个独立导航页：

- 资源完整性
- 运行信号
- 触发器目录
- API 契约检查

底层只读端点可继续复用，但页面不得输出裸 JSON。页面分为：

1. **综合摘要**：缺失资源数、需关注运行信号数、已注册/有样本触发器数、契约漂移数。
2. **资源与配置**：功能是否具备素材、开关是否关闭、缺失项如何修复；人工维护的 known gaps 必须与代码真值分开展示。
3. **运行健康**：进程级信号按严重度、分类、次数、最近时间聚合；明确“本进程重启后清空”。
4. **主动链路**：触发器注册、最近提议、gating/发送结果。seed prompt、搜索条件和 LLM 输出默认不展示，需显式展开且保持 `memory.read` 权限。
5. **桌面兼容**：后端 action 与桌面客户端消费者的静态契约差异；明确这不是在线连通测试。

页面顶部不得只有一个模糊的“系统正常”。每个检查项必须标注检查层级：静态资源、当前进程、调度链路、跨仓源码契约或真实通道。

## C. 全局 i18n 可逆修复

### C1. 根因修复

- 修复 `admin/static/i18n.js` 的旧文本翻译，使任意页面在以下顺序中均可逆：
  - 中文启动 → 英文 → 中文；
  - 英文启动 → 首次懒加载页面 → 中文；
  - 英文下访问多个页面 → 中文 → 再访问此前未加载页面；
  - 切换语言后重新加载当前 fragment。
- 不得依赖“当前 DOM 第一次看到的文本一定是中文”。原文必须来自稳定的中文词典、显式 `data-i18n` key，或在翻译前可靠捕获的模板源。
- 新增/改动页面的所有可见静态文字必须使用语义 `data-i18n` key；不得继续扩大 legacy 文本扫描覆盖面。
- `.i18n-raw` 只用于 authored/runtime 内容、日志、Prompt、用户文本和协议字段，不得用它掩盖遗漏的界面翻译。
- fragment 加载完成后显式对 fragment 根调用 `AdminI18n.applyI18n(root)`，行为不能只依赖 MutationObserver 的时序。

### C2. 回归测试

- 添加 DOM 测试，模拟懒加载 fragment 和上述四种切换顺序。
- 扫描所有 `admin/static/pages/*.html` 与动态模板：中英文语义 key 成对存在；中文模式不得残留已知英文 UI 文案，英文模式不得残留未豁免中文 UI 文案。
- authored/runtime 内容必须在两种语言下保持逐字不变。

## D. 「对话与角色 → 用户数据」

### D1. 页面目标

新增 `user-data` 页面，提供“已有资产清单 + 安全上传 + 绑定状态 + 删除确认”。不重复管理已有的：

- 角色卡
- 现实/梦境破限预设
- 世界书

首期分类：

- 通用表情包 `userdata/assets/stickers/{emotion}/`
- 角色专属表情包 `userdata/assets/stickers_packs/{pack}/{emotion}/`
- 角色声音资产 `userdata/characters/authored/{char_id}/voice/`
  - 参考音频
  - GPT 模型文件或受支持的模型引用
  - SoVITS 模型文件或受支持的模型引用
- Live2D 模型包
- 3D 模型包
- 其他已有 authored 资产只读清单：活动池、author notes、traits、信件样本和知识资料；本 Brief 不提供这些结构化文件的任意覆盖上传。

### D2. 资产契约

- 为声音、Live2D、3D 建立明确的 canonical `userdata/` accessor、registry 条目、允许格式、大小上限和逻辑 ID。
- 上传必须使用服务端生成/校验后的目标路径，拒绝绝对路径、`..`、驱动器前缀、符号链接逃逸、重复分隔符和不受支持扩展名。
- 多文件模型包必须作为整体校验：
  - Live2D 入口为 `*.model3.json`，引用的纹理、moc、motion、expression 不得逃逸包目录；
  - 3D 首期只接受桌面端真实支持的格式和配套文件。不得因为后缀是 `.glb`/`.vrm` 就宣称可渲染。
- 上传先进入同一 `userdata/` 根内的临时目录，完整校验通过后原子落位；失败不得留下半包。
- 同逻辑 ID 已存在时不得静默覆盖；提供“取消 / 另存为 / 明确替换”流程。替换必须保留可恢复备份或使用原子交换。
- 清单返回逻辑 ID、类别、角色作用域、大小、更新时间、有效性、有效读取来源和绑定使用者；不得向前端返回本机绝对路径。
- `bundled` / legacy fallback 可显示为只读来源，不能通过此页删除。

### D3. Live2D/3D 跨仓约束

这是跨仓功能，必须先以现有桌面实现为真值定义消费方式：

- 后端上传的模型必须能被桌面端通过受鉴权的清单/文件接口或明确的安装动作实际取得。
- 禁止返回任意文件系统路径，禁止开放通用静态目录浏览。
- 桌面端必须校验相对路径、MIME/扩展名、下载大小和包完整性，并保存到现有客户端私有模型目录或从受控 URL 加载。
- 更新角色 `live2d_model` / `model_3d` 绑定时使用逻辑资产 ID，不再要求用户手输本机路径。
- 如果本 Brief 的实现批次只完成后端托管而未完成桌面消费，页面必须显示“已上传，桌面端尚不可用”，该项状态为 partial，不能验收为完成。

### D4. 删除确认

- 删除使用 `admin` scope；列表/观测至少使用 `persona`，敏感文件详情按现有权限模型收紧。
- 删除前服务端返回影响分析：绑定到哪些角色/TTS preset、是否为当前有效资产、是否只有 legacy/bundled fallback。
- UI 必须显示资产名、类别、作用域和影响，并要求二次确认；当前被绑定资产默认拒绝删除，必须先解除绑定或通过明确的“解除绑定并删除”动作。
- 目录/包删除必须精确到单个已校验资产根；不得接受任意路径或递归删除宽泛目录。
- 删除后提供成功/失败明细并刷新有效来源；记录不含正文和本机绝对路径的审计事件。

## E. TTS 自动发现与角色选择

### E1. 角色作用域

- 在系统状态的 TTS 卡片顶部新增角色下拉框，同时保留“全局默认”选项。
- 选择角色后显示：角色名、绑定的 `tts_preset`、该 preset 是否存在、每个字段来自角色 preset 还是全局回落。
- 保存角色配置不得直接污染全局配置：
  - 用户选择已有命名 preset，或创建新的命名 preset；
  - 保存后通过现有 `presence_ext.tts_preset` 绑定到所选角色；
  - 清除绑定时明确提示将回落全局配置。
- 试听请求必须携带所选 `char_id`，使用与真实 `voice_adapter.synthesize(..., char_id=)` 相同的解析链路；不得只试听全局配置却标成角色效果。

### E2. 资源选择器

- 将以下自由文本路径改为选择器：参考音频、GPT 模型、SoVITS 模型。
- 选项来源优先级：
  1. 「用户数据」中已校验的角色声音资产；
  2. GSV provider 官方支持的模型枚举接口或已注册模型 ID（仅在可探测且返回可信结构时）；
  3. 当前已有配置值，若不在清单中，以“外部/不可验证的旧配置”只读显示，允许保留或改选，不得静默清空。
- 后端不得扫描任意磁盘或把绝对路径返回给浏览器。远端 GSV 服务没有模型枚举能力时，明确显示“服务不支持自动发现”，不能假装读取远端文件系统。
- 下拉项显示易懂名称、类型、角色、来源、有效性；提交保存逻辑 ID或受控相对路径，由服务端解析成 provider 所需值。
- 情绪分档的参考音频也使用同一资产选择器；不得只修默认 `ref_audio`。
- Provider 切换继续保留各 provider 参数快照，不能因为改成选择器而丢失其他 provider 配置。

## 非目标

- 不删除生产 `userdata/` 或 legacy 资产，不执行自动迁移。
- 不把 `data/runtime/` 记忆、聊天历史、Dream archive 等运行态混进「用户数据」上传管理。
- 不在浏览器中提供任意文件管理器、任意路径读取或目录遍历。
- 不用 API 契约静态检查冒充真实 E2E 通道健康。
- 不把 authored/runtime 内容翻译成另一种语言。
- 不新增未被当前桌面渲染栈支持的 3D 格式。

## 建议实施顺序与提交边界

每项相关测试和差异检查通过后立即做独立 commit，再开始下一项：

1. **158-A：i18n 可逆修复**——先消除跨页面半英半中，避免后续新页面复制缺陷。
2. **158-B：存在与系统诊断重组**——导航、聚合 view-model、可读 UI，移除裸 JSON 前端页面。
3. **158-C：用户数据后端资产契约**——路径、registry、清单、上传、校验、影响分析、删除确认 API。
4. **158-D：用户数据管理页面**——双语 UI、上传/观测/绑定/删除流程。
5. **158-E：TTS 角色化与资源选择**——角色 preset 绑定、自动发现、情绪参考音频、真实角色试听。
6. **158-F：Live2D/3D 桌面消费闭环**——仅在协议和安全边界确认后跨仓实施并独立提交。

## 验收标准

- 主导航只出现一个「存在」入口组，包含记忆、成长、支出、视觉和群聊仲裁；原 deep link 不报错。
- 情绪、花园、梦境、记忆、隐性状态和系统诊断均不再以裸 JSON 作为正常页面内容。
- 系统诊断能区分资源、进程、触发器、源码契约和真实通道层级。
- 中英文在已加载/未加载/重新加载 fragment 的所有顺序下完整可逆，界面文案无半英半中；用户内容保持原文。
- 用户数据页能列出有效来源，安全上传受支持资产；legacy/bundled 只读；覆盖和删除均不能静默发生。
- 删除被角色或 TTS preset 使用的资产会被阻止或要求明确解除绑定；服务端再次校验，不依赖前端确认。
- TTS 可选择全局或角色；角色有效来源清晰，模型和参考音频无需手填地址，旧外部配置不会被静默破坏。
- 角色试听走真实 `char_id` 配置解析链。
- Live2D/3D 只有在桌面端能实际列出并加载后才可标为可用。

## 验证

- 后端 focused tests 使用 `pytest -n auto` 或指定文件并行运行；临时目录按 `docs/dev-environment.md` 设置到仓库内。
- 覆盖：路径逃逸、恶意压缩包、符号链接、超限文件、半包回滚、重名、绑定删除、legacy 只读、权限 scope、绝对路径脱敏。
- 扩展 admin static/i18n 测试，覆盖 fragment 懒加载与双向语言切换。
- 对所有修改的 JS 执行 `node --check`。
- 浏览器人工验收桌面与窄屏布局；检查状态卡、空态、错误态、确认框和键盘可访问性。
- 若修改 `admin/static/pages/`，更新 `ADMIN_UI_FRAGMENT_VERSION` 及 `index.html` 的 `core.js?v=`；若修改直接加载的 JS/CSS，同步更新对应 `?v=`。
- 若实施 Live2D/3D 跨仓消费，执行桌面端 focused tests/build，并以真实上传包完成一次“上传 → 列出 → 绑定 → 桌面加载 → 删除保护”E2E。
- `git diff --check`，并审计每个 commit 只包含本子任务文件。
