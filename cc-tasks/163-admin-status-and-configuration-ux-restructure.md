# Brief 163：系统状态与配置页面减负、TTS 独立化及参数语义化

## 背景

当前“系统状态”页同时承担运行摘要、配置写入、调试参数、危险模式、代理、视觉、Relay、TTS 等职责。部分内部参数直接暴露，boolean 可能通过通用键值编辑器手填 `true/false`，TTS 表单占据很长页面；`Data isolation` 也没有解释其只读诊断含义。

本 Brief 将状态展示与配置编辑分层：状态页负责回答“现在是否正常、什么正在生效、去哪里修改”，配置页负责语义化编辑，高级 JSON/键值编辑器只作为折叠的专家模式。

## 目标

- 系统状态页变成可快速扫描的只读摘要。
- 常用配置使用开关、三态选择、枚举、带单位数字控件等语义化组件。
- TTS 从状态页的大段表单中拆出独立配置区，状态页只保留摘要和入口。
- 将 `Data isolation` 改成普通用户能理解的“当前数据环境”。
- 保留高级 JSON 能力，但不再把它作为主要交互。

## 范围

### A. 系统状态页职责

状态页默认只展示：

- 已知用户/基础运行摘要；
- 当前数据环境；
- 当前模型连接与路由摘要；
- TTS 摘要；
- 代理摘要；
- 调度/通道摘要；
- 最近错误或需要关注项；
- 明确的“进入配置/查看详情”入口。

每张摘要卡至少显示：当前值、配置来源、是否生效、最后刷新/错误状态。不得把 HTTP 200 或配置存在等同于真实外部链路可用。

### B. 当前数据环境

- 将 `Data isolation` 改为：
  - 中文：`当前数据环境`
  - 英文：`Current data environment`
- 增加只读说明：用于确认当前进程读写正式数据还是测试沙箱，防止测试数据污染正式用户数据。
- 字段改为可读名称：
  - 运行模式：正式数据 / 测试沙箱；
  - 测试会话：无 / 会话标识；
  - 数据存储位置：脱敏逻辑位置；
  - 隔离测试用户：无 / 数量与说明。
- 不显示本机绝对路径、内部用户明细或可编辑数据根。

### C. TTS 独立配置

- 状态页 TTS 卡只显示：
  - 启用/关闭；
  - 当前 Provider；
  - 当前角色绑定/全局回退；
  - 参考音频与模型配置完整性；
  - Provider 是否就绪；
  - 最近一次合成结果；
  - “进入 TTS 配置”按钮。
- 将完整 TTS 编辑器放入独立页面或明确的配置子页。
- 独立页保留角色作用域、provider 切换、参考音频、GPT/SoVITS 模型、参考文本、语速、情绪分档、桌面语音条、试听和调用记录。
- 复用用户数据页的分类资产选择结果，不重新退化为手填物理路径。
- Provider 高级参数默认折叠，并显示密钥只写、来源和切换 provider 的未保存更改提示。

### D. 配置控件语义化

- boolean 使用 checkbox/switch；有继承语义时使用“继承/启用/关闭”三态控件。
- 不允许常用配置要求用户手填 `true` 或 `false`。
- 枚举使用 select/radio；数值使用 number/range 并显示单位、范围和默认值。
- key/value 高级编辑器对 boolean 类型提供选择器，不使用自由文本值。
- 每个配置项提供：
  - 用户可读名称；
  - 一句用途；
  - 当前来源；
  - 修改后的生效方式（即时、热重载、重启）；
  - 恢复继承/默认值操作（契约允许时）。
- 内部 key 可作为次级 code 标签保留，不作为唯一 label。

### E. 高级 JSON/键值视图

- 保留折叠的“高级配置/原始参数”区域，供诊断和特殊 provider 参数使用。
- JSON/键值编辑器必须校验类型，保存失败时指出具体字段。
- 密钥字段不回显；只读运行时数据不得伪装成可编辑 JSON。
- 常用表单与高级视图必须使用同一份状态，不允许互相覆盖未保存修改或产生两个真值来源。

### F. 页面组织与 i18n

- 按现有导航能力决定新增独立 `TTS 配置` 页面或配置页子入口；不得让状态页继续承载完整编辑器。
- 系统状态、配置、TTS、Data environment 的所有静态/动态文案完整支持中英文实时切换。
- 新增语义化样式复用 Brief 159 的表单控件基础，不另建平行样式体系。
- 窄屏卡片、表单、按钮和高级 JSON 区不得溢出。

### G. 文档同步

- 若移动模型路由、TTS、relay、scheduler、thinking、tool loop 或高级功能开关入口，同步更新 `docs/feature-control-surface.md`。
- 文档记录“页面位置、配置来源、生效方式”，不得写入本机路径或密钥。

## 不在范围内

- 不修改业务配置 schema，只为现有契约建立更清晰的 UI。
- 不把系统状态页改成通用 YAML/JSON 编辑器。
- 不新增未经后端支持的即时生效、重启或健康检查承诺。
- 不把 TTS API 成功等同于真实扬声器播放或桌面端完整 E2E。
- 不移动、删除或重写真实用户数据。
- 不顺带重构模型路由、scheduler 或 tool loop 的运行时架构。

## 验收标准

- 状态页首屏可以快速看懂运行摘要，不再出现完整 TTS 长表单。
- `Data isolation` 不再作为可见标题；“当前数据环境”能解释正式数据与测试沙箱，且不泄露绝对路径。
- 常用 boolean 配置无需手填 `true/false`；继承语义使用三态控件。
- TTS 独立配置页能完成现有功能，状态页入口清晰，保存 payload 与原 API 一致。
- 高级 JSON/键值区可折叠、类型安全、密钥不回显，与常用表单没有双真值。
- 页面明确区分配置存在、Provider 就绪、API 调用成功和真实客户端播放。
- 中英文、宽屏、窄屏、空状态、失败状态均完成浏览器目检；未完成则标记 partial。

## 验证

- 运行 status/settings/TTS/admin static/admin i18n focused tests（pytest 使用 `-n auto`）。
- 增加 DOM/静态测试覆盖状态摘要、TTS 独立入口、boolean/三态控件、Data environment 脱敏和高级区折叠。
- 对所有修改的 JS 执行 `node --check`。
- 若 fragment 改动，更新 `ADMIN_UI_FRAGMENT_VERSION` 与 `core.js?v=`；直接加载 CSS/JS 同步更新对应 `?v=`。
- 浏览器目检保存、刷新、语言往返、provider 切换、未保存提示和窄屏。
- 执行 `git diff --check`，确认不夹带其他 Brief 的改动。

## 建议施工顺序与提交边界

本 Brief 内可按以下顺序实施，但在全部相关测试和 UI 验收完成后形成一张独立 commit：

1. 状态页摘要与“当前数据环境”；
2. TTS 独立页面及入口迁移；
3. boolean/三态与高级配置编辑器；
4. i18n、文档、缓存版本和回归测试。
