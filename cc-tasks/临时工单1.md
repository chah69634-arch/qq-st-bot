按当前审计方案实现 Tool Ephemeral Status P0，但做以下边界修订：

1. 在 run_agentic_loop() 增加可选 tool_event_observer，只发送本地结构化瞬态事件：
   pending_confirmation / queued / waiting / finished / failed /
   outcome_unknown / cancelled。

2. 瞬态事件不得调用 record_assistant_turn()，不得写入 short_term、
   event_log、identity、情绪分析、记忆后处理或后续 prompt history。

3. 增加 ephemeral tool speech/status 出口：
   - 可显示临时气泡；
   - 可选 TTS；
   - 必须带 TTL；
   - 不作为正式 assistant turn；
   - 不允许触发表情包、贴纸、action trace 或二次工具调用。

4. 前置提示只能在参数校验、权限校验和确认闸门通过后发送。
   在真实工具结果前不得声称“设备已经开始”“操作成功”或承诺结果。
   一期使用受控模板，不展示模型 tool-call 原始 content。

5. MCP 没有真实进度协议。一期 waiting 只能表达“仍在等待回应”，
   不生成百分比、阶段或设备已动作等推断。

6. 重试期间保持同一个状态实例并更新 attempt，不重复创建“开始执行”
   气泡。McpOutcomeUnknown 必须映射为 outcome_unknown，不能映射为
   failed/completed/safely_stopped。

7. conversation_lock 继续覆盖完整 agentic loop，普通消息不得插队。
   但审计并保留独立 cancel/emergency_stop 抢占通道；不要让硬件停止请求
   被普通 conversation_lock 阻塞。若当前尚无安全抢占能力，只记录为明确
   blocker，不要伪造取消成功。

8. 多工具保持串行，状态显示当前 index/total，不暗示并发。

9. 桌面端新增协议类型时，同步更新 desktop-client-protocol 和客户端类型/
   handler；后端不得单边发送未知事件。

10. 移动端不得复用持久离线消息队列承载瞬态状态。使用 TTL 临时事件；
    若当前移动端没有在线瞬态通道，P0 先仅支持桌面并明确记录限制。

11. 最终自然回复保持现有 LLM 收尾流程，并且整轮只写入这一条正式
    assistant turn。

12. 补测试覆盖：
    - confirmation 前无前置提示；
    - waiting 超阈值仅发送一次；
    - retry 更新同一状态；
    - outcome_unknown 文案和状态准确；
    - 状态不进入任何记忆写路径；
    - 最终回复仍正常写入；
    - 多工具串行 index 正确；
    - TTL 过期状态不可重放；
    - cancel/emergency_stop 不被普通对话锁阻塞，或被明确标记为当前 blocker。

不要在 P0 实现伪进度，也不要修改 MCP 协议来猜测硬件 started/progress。
真实设备排队、开始、阶段、完成事件留给 presence_hardware MCP 后续主动上报。
